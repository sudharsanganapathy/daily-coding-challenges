# ⏱️ Time & Space Complexity

Every DSA solution is analyzed for:

### ⏱️ Time Complexity

How the number of operations grows as the input size increases.

### 💾 Space Complexity

How much additional memory the algorithm requires.

### Examples

| Problem | Time Complexity | Space Complexity |
|---|---:|---:|
| Move Zeroes | O(n) | O(1) |
| Missing Number | O(n) | O(1) |
| Two Sum - Brute Force | O(n²) | O(1) |
| Merge Intervals | O(n log n) | O(n) |
| Palindrome | O(n) | O(1) |
| String Compression | O(n) | O(n) |
| Reverse Each Word | O(n) | O(n) |
| Valid Parentheses | O(n) | O(n) |
| Rotate Array | O(n) | O(1) |
| Isomorphic Strings | O(n) | O(n) |
| Valid Anagram - Sorting | O(n log n) | O(n) |
| Binary Search | O(log n) | O(1) |
| Remove Stars | O(n) | O(n) |

# 🔍 Problem Analysis Workflow

For every new DSA problem, I follow this process:

```text
1. Understand the problem
        ↓
2. Identify input and output
        ↓
3. Think about the brute-force solution
        ↓
4. Look for a better pattern
        ↓
5. Choose the right data structure
        ↓
6. Write the solution
        ↓
7. Trace the solution manually
        ↓
8. Analyze Time Complexity
        ↓
9. Analyze Space Complexity
        ↓
10. Revise the problem later
```

# 🔄 Revision Strategy

Solving a problem once is not enough.

Previously solved problems are revisited to improve:

- 🧠 Pattern recognition

- ✍️ Implementation speed
- 🎯 Interview explanation
- ⏱️ Complexity analysis

### Revision Cycle

```text
Solve
  ↓
Understand
  ↓
Trace
  ↓
Explain
  ↓
Revisit
  ↓
Solve without reference
```

The goal is to eventually recognize the underlying pattern when facing a new problem.
